## Analytics design (builder)

- Single module `lib/analytics/events.ts` owning the eight SPEC events and a strict allowlist: `assessment_cta_click{placement,service_category}`, `assessment_form_start{page_template}`, `assessment_submit_attempt{service_category,property_category,region,urgency_category}`, `assessment_validation_error{error_class,field_category}`, `assessment_delivery_error{error_class}`, `Lead Submitted{service_category,urgency_category}` (existing name; once per logical request ID, never on replayed retry UI state), `emergency_call_click{placement}`, `maintenance_interest_click{placement}`. Every property value is mapped through enumerations (unknown → `other`/`unknown`); no free text, contact fields, city strings (region = orlando/tampa/other/unknown from the existing location data only), request IDs, full URLs or query strings. Analytics exceptions are swallowed and never alter form/delivery state.
- Pageviews: disable automatic capture and send manual pageviews with a sanitized URL = production origin + canonical pathname (known route inventory; unknown → `/404`) + only `utm_source`/`utm_medium`/`utm_campaign` normalized to `^[a-z0-9._-]{1,40}$` (else `other`). Referrer reduced to origin only (or removed) via the tracker's `transformRequest` if the pa- script supports it; builder must confirm from the installed/official tracker source and record the evidence. If it cannot be controlled, record the exact residual behavior as a limitation for Brian rather than claiming sanitization.
- Script only renders when `NEXT_PUBLIC_PLAUSIBLE_SCRIPT_URL` is an `https://plausible.io/js/pa-*.js` URL and the environment is neither local preview nor hosted preview (existing guards). Build-time and runtime both off in preview.
- Form/CTA/phone hooks are minimal attribute/handler additions; no copy or visual change.

## Release tests (test-guard)

- `test:release` (Playwright JSON report; registered in harness/verification.json by the orchestrator): Chromium, Firefox and WebKit projects against the compiled isolated local server covering home → contact assessment success (local receipt), validation errors with focus/summary, known failure (FSC_LOCAL_FAILURE server), unknown/504 retry with the same request ID (route interception), emergency direct entry/back-forward consistency, mobile 390 and desktop 1440 overflow, keyboard-only submit, 200% zoom/reflow spot checks, reduced motion, axe (no critical/serious) on representative route families.
- Analytics payload capture: serve the official Plausible tracker build from a pinned dev dependency (e.g. `@plausible-analytics/tracker`) at the intercepted script URL in a test-only build with a synthetic script URL; intercept `/api/event` POSTs; assert event names, property keys/values against the allowlist, sanitized `u`/`r`, zero contact values, `Lead Submitted` exactly once per logical request, no analytics in local/hosted-preview builds. Never contact plausible.io.
- Lighthouse: pinned `lighthouse` dev dependency using Playwright's Chromium, mobile preset, three runs per representative URL (home, contact, services, one industry, one area, one article) against the compiled loopback server; store raw JSON reports and a median summary under harness/evidence; fail if the evidence manifest is missing. Targets Performance ≥90, Accessibility ≥95, Best Practices ≥95, SEO ≥95 are reported honestly; a miss is a finding for repair or an explicit documented exception, never a silent pass. Note local-loopback caveats (noindex on local preview affects SEO audit — measure with an isolated non-preview compiled build that still has delivery and analytics disabled, or record the exception).
- Existing floor preserved; physical device, real screen reader and field Core Web Vitals are recorded as not available unless actually performed.
