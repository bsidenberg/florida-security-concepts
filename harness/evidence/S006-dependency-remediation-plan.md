# Narrow dependency remediation — 2026-09-14

**Recommendation: use Next 15.5.25 (current maintenance backport), matching eslint-config-next, patched PostCSS, and the smallest Resend patch; verify the resulting lockfile before release. Do not run `npm audit fix --force` into Next 16.** No packages or application files were changed by this investigation.

## What the audit does and does not establish

- The two critical Next advisories are fixed starting at **15.5.24**. Current Next 14.2.35 is unsupported; 15.x is Maintenance LTS, so 15.5.25 is the narrow supported branch choice available today. Its support horizon is short (policy: two years from October 2024), so schedule a later Next 16 migration. [Next support policy](https://nextjs.org/support-policy), [August security release](https://nextjs.org/blog/august-2026-security-release), [15.5.25 release](https://github.com/vercel/next.js/releases/tag/v15.5.25).
- Windows RCE GHSA-p293-qw3h-jr36 specifically concerns a Windows filesystem. This local compiled server runs on Windows, but binds loopback; the version finding does not prove public exposure or exploitation. Linux/macOS are not affected by this particular flaw. [Primary advisory](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36).
- AVIF RCE GHSA-2xp9-vwfh-vxw4 involves optimizing attacker-controlled AVIF input. Configuration enables AVIF output, but that alone does not establish attacker control of image input. No next/image usage, AVIF asset or remotePatterns was found in inspected application paths. Patched Next disables the affected AVIF optimization path. Vercel reports managed image-service protections and Linux hosting protection for these two issues; that does not patch the local Windows dependency or resolve other advisories. [AVIF advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4), [Vercel protection statement](https://vercel.com/changelog/nextjs-august-2026-security-release).
- Other audit findings depend on features/configuration: no rewrites, custom WebSocket upgrade, middleware/i18n, CSP nonce or beforeInteractive untrusted script use was found in the inspected paths. App Router/Server Components are present, so their DoS findings cannot be dismissed. Upgrade fixes the reported Next ranges; no exploit probes are required.
- **Next 15.5.24 and 15.5.25 both still declare PostCSS 8.4.31.** A Next upgrade alone therefore does not remove the separate PostCSS audit findings. Those concern processing attacker-influenced CSS/source maps; this site has no exposed CSS-processing/upload endpoint. Use patched PostCSS nonetheless. The final incomplete source-map fix starts at 8.5.23; current registry release is 8.5.28. [PostCSS advisory](https://github.com/postcss/postcss/security/advisories/GHSA-fxqj-rqcc-2cmp).
- Resend -> svix -> uuid is a transitive chain, not three independent application exploits. UUID advisory affects v3/v5/v6 caller-supplied buffers, not the application's `crypto.randomUUID()`. Resend 6.12.3 declares svix 1.92.2, outside the audited svix affected range. Confirm its resolved UUID is patched with a fresh audit; no need to jump automatically to Resend 6.28.0. [UUID advisory](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq).

## Small migration scope

1. Pin `next` and `eslint-config-next` to 15.5.25; pin Resend 6.12.3. Pin direct PostCSS 8.5.28 and add a narrow Next -> PostCSS override to 8.5.28, documenting the override and verifying production CSS output. Regenerate lockfile normally; no forced peer dependency bypass.
2. Resolve React explicitly: Next's registry peer range accepts React/ReactDOM ^18.2, but the **App Router** migration guide specifies React 19. Do not equate permissive peer installation with supported App Router compatibility. Recommended migration uses matching stable React/ReactDOM 19 and matching @types packages; registry current stable is 19.3.0. next-plausible 4.0.0 peers permit React 19 and Next 15. If retaining React 18 is proposed to minimize churn, require explicit supported-App-Router evidence first. [Official v15 upgrade guide](https://nextjs.org/docs/app/guides/upgrading/version-15).
3. Await `params` in the four `app/{services,industries,service-areas,resources}/[slug]/page.tsx` pages and metadata functions; await optional `searchParams` in `app/contact/page.tsx`. Update their types to Promise forms. This is framework compatibility, not business behavior change. Review GET/fetch caching defaults; preserve intentional static routes and explicit lead API dynamics. No cookies/headers usage requiring conversion was found.
4. Retain Node 24 (15.5.24 registry permits >=20), existing test framework and webpack flow. Validate the internal `next/dist/server/lib/start-server` local helper against 15.x; do not silently relax isolation. `next lint` remains available in 15, but verify matching lint package behavior.

## Required evidence before calling it repaired

- Fresh `npm audit --omit=dev --json` plus `npm ls next react react-dom postcss resend svix uuid`: show actual resolved patched versions and inspect any remaining findings; do not infer zero vulnerabilities from proposed pins.
- Existing full machine gate with **at least the observed 190-test floor**; typecheck must include generated route types. Run real compiled local boot/receipt under the new runtime, not only mocked API tests.
- Recheck all 38 routes, metadata/canonical/schema/query behavior, emergency history, retry/durable receipt and privacy isolation; preserve current route inventory under approved content deferral.
- Review CSS/theme screenshots and image responses after PostCSS/Next changes; ensure malformed image requests are rejected without testing exploit payloads. Keep external requests and live provider sends blocked during local tests.
- Cross-browser release checks can now use Firefox/WebKit installed by parent; run after the upgrade, avoiding duplicate pre-upgrade matrices. Independent reviewer/verifier records the resulting evidence.
